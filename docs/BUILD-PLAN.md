## Архитектура: три части

```
┌─────────────────────────┐         ┌──────────────────────────────┐
│  ФРОНТЕНД  frontend    │         │  БЭКЕНД                      │
│  Next.js, :3001          │         │                              │
│  (все экраны готовы)     │         │  ┌────────────────────────┐  │
│                          │◄──WS───►│  │ Tinode (движок чата)   │  │
│  ┌──────────────────┐    │ tinode  │  │ :6061 + gRPC :16061    │  │
│  │ tinode-sdk       │────┼─────────┼─►│ + наша мини-правка     │  │
│  │ (чат/медиа)      │    │         │  │   анонимности          │  │
│  └──────────────────┘    │         │  └───────────▲────────────┘  │
│  ┌──────────────────┐    │         │              │ gRPC (ROOT)   │
│  │ companion-client │────┼──REST───┼─►┌───────────┴────────────┐  │
│  │ (логин/рулетка/  │    │  + WS   │  │ Companion (Go, наш код)│  │
│  │  друзья/деньги)  │    │         │  │ + Postgres (anoon)      │  │
│  └──────────────────┘    │         │  └────────────────────────┘  │
└─────────────────────────┘         └──────────────────────────────┘
```

- **Фронт ↔ Tinode** (WebSocket, библиотека `tinode-sdk`): сами сообщения, «печатает», статусы,
  медиа, голос, presence друзей.
- **Фронт ↔ Companion** (свой REST + WebSocket): вход/OAuth, рулетка-подбор, #ID, заявки в друзья,
  жалобы, статус бана, подписки/монеты, anoon-события (нашёлся собеседник, пришла заявка).
- **Companion ↔ Tinode** (gRPC как ROOT-бот): создаёт анон-топики, подписывает пары, снимает шторку
  при раскрытии, бан (state) / мьют (право W), брокерит OAuth через `rest`-схему.

## Фронтенд — что делаем (frontend уже есть, подключаем)

Экраны готовы (мессенджер + рулетка, PWA, вьювер). Работа — заменить моки на реальные данные:

1. **Слой данных.** Добавить два клиента:
   - `tinode-sdk` (npm) — обёртка над Tinode. Подключение, логин по токену, подписка на топики,
     отправка/приём сообщений, «печатает», статусы, загрузка медиа.
   - `companion-client` — тонкий свой клиент (fetch + WebSocket) к нашему API.
2. **Состояние.** Хранилище (Zustand/Context) на: текущий пользователь+#ID, список чатов/друзей,
   активный анон-чат, очередь рулетки, уведомления, статус подписки/монеты.
3. **Экран за экраном — убираем моки:**
   - Вход/регистрация → companion (OAuth + email) → получаем Tinode-токен, открываем Tinode.
   - Главная/поиск → companion `/roulette/*`.
   - Анон-чат → подписка на анон-топик через tinode-sdk (сообщения родные, лица скрыты правкой).
   - Друзья/заявки/личка → друзья через companion, переписка через Tinode.
   - Уведомления/жалобы/профиль/настройки → companion.
4. **Реалтайм-события** (нашёлся собеседник, заявка, раскрытие, бан) — по companion-WebSocket.
5. **PWA/офлайн/пуши** — уже есть каркас; пуши подключаем в отдельной фазе.

> Примечание: `frontend` — отдельное Next.js-приложение (не тот webapp, что внутри Tinode).
> Библиотека `tinode-sdk` подключается как обычный npm-пакет.

## Бэкенд — что делаем

### Tinode (движок, уже работает)
- **Мини-правка анонимности** (вариант E, ~3 точки + флаг) — обнулить личность в анон-топике.
  Точки: `prepareBroadcastableMessage` `topic.go:279` (Data.From + Info.From), `replyGetData`
  `topic.go:2794` (история), `replyGetSub` `topic.go:2633/2693` (peer UID/Public). Пересобрать
  свою сборку из `server-stack`, протестировать.
- Больше ядро не трогаем (стоковое, апгрейды лёгкие).

### Companion (наш сервис на Go — пишем с нуля)
- **Каркас:** Go-сервис в `server-stack` compose, сеть `tinode-net`; своя БД `anoon` в том же
  postgres:16; миграции; health.
- **ROOT-бот:** постоянное gRPC-подключение к Tinode (`server/chatbot`-паттерн), аккаунт помечен
  `tinode-db --make_root`. Через него создаём топики, подписываем, баним, снимаем W.
- **Auth:** реализовать `rest`-endpoint для Tinode + OAuth-брокер (Google) + email/пароль (basic).
  Выдача #ID, хранение пола/возраста.
- **Свой API наружу:** REST + WebSocket для фронта (рулетка, друзья, жалобы, деньги, события).

## Порядок работ (фазы)

### Фаза A — Фундамент бэкенда
- [ ] A1. Мини-правка анонимности в Tinode + пересборка + тест (два аккаунта, личность скрыта).
- [ ] A2. Каркас companion на Go: БД `anoon`, миграции, ROOT-бот подключается к Tinode, health.
- [ ] A3. Auth: `rest`-endpoint + Google OAuth + email/пароль; выдача #ID; пол/возраст.

### Фаза B — Подключаем вход на фронте
- [ ] B1. Вшить `tinode-sdk` и `companion-client` в frontend; хранилище состояния.
- [ ] B2. Реальный вход (Google + email) от кнопки до открытого Tinode-соединения.
- [ ] B3. Настоящий профиль + #ID на экранах.

### Фаза C — Ядро: друзья и рулетка
- [ ] C1. Друзья: реальный список/заявки/поиск по #ID (companion) + личная переписка (Tinode).
- [ ] C2. Рулетка: очередь+подбор в companion (приоритет платных), создание анон-топика, событие
  «нашёлся» на фронт.
- [ ] C3. Анон-чат на фронте через Tinode (текст, «печатает», статусы; медиа/голос — если решим
  включать сразу). Онлайн-точку даёт companion.
- [ ] C4. Завершение + оценка; «Раскрыть профиль» → снятие флага → дружеский чат (та же переписка).

### Фаза D — Модерация и деньги
- [ ] D1. Жалобы (таблица companion), бан (state), мьют (снятие W, срок в companion).
- [ ] D2. Подписки Premium/Super Premium, монеты, приоритет очереди; оплата (Idram/Telcell/ArCa).
- [ ] D3. Бэкенд-данные для админки (онлайн, чаты read-only, файлы) — если беёмся за админку.

### Фаза E — Пуши и прод
- [ ] E1. Web-push (VAPID) + рассылка от админа.
- [ ] E2. Прод-деплой: VPS/Fly/Railway, TLS, домен; армянские платёжки в бою.

## «Готово» для первого рабочего куска
Фазы A–C: человек регистрируется через Google, получает #ID, находит собеседника в анонимной
рулетке, общается (лицо скрыто), раскрывает профиль, становится другом, переписывается в личке.
Деньги и модерация (D), пуши/прод (E) — следом.

## Связь с бизнесом (BUSINESS-PLAN.md)
- Приоритет очереди платных → закладываем в матчинг companion (Фаза C2).
- Запуск узкий (Ереван, часы активности) → сначала важна плотность, а не полнота фич: можно
  Фазу C3 начать с текста, медиа/голос добавить после проверки, что люди возвращаются в прайм-тайм.
