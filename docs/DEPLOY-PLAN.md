## 1. Рекомендация хостинга: **Hetzner Cloud VPS (Германия)**

### Сравнение для нашей нагрузки (Tinode + companion + Postgres + медиа, WebSocket-heavy, аудитория в Армении)

| | **Hetzner VPS** ✅ | Fly.io | Railway | DigitalOcean |
|---|---|---|---|---|
| Цена на старт | **CX32: €6.80/мес** (4 vCPU, 8 GB RAM, 80 GB NVMe, 20 TB трафика) | ~$10–20 машины + **$38/мес** Managed Postgres (или самодельный PG на volume) | $5–20/мес + usage; egress **$0.10/GB** — дорого для медиа | droplet 4 GB ~$24/мес, трафик лимитней |
| Пинг из Еревана | **~57 мс** (Nuremberg/Falkenstein) | ~56 мс (fra), но платим за каждый ресурс отдельно | зависит от региона (EU-west, ~70+ мс) | ~56 мс (FRA1) |
| WebSocket / долгие соединения | нативно, без ограничений | ок | ок, но usage-биллинг за RAM-часы | нативно |
| Постоянные диски / volumes | входит в цену | $0.15/GB/мес отдельно | $0.25/GB/мес | входит |
| S3-хранилище рядом | **Object Storage €4.99/мес за 1 TB + 1 TB egress** | нет своего (нужен R2/B2) | нет своего | Spaces $5/мес/250 GB |
| Контроль (наш патч-образ, докер-компоуз как локально) | **полный — тот же docker compose** | свой rуntime (flyctl, Machines) | свой рантайм | полный |

**Вывод:** платформы (Fly/Railway) не дают ничего критичного для этой нагрузки, а Managed Postgres на Fly ($38/мес) один стоит дороже всего нашего VPS. Hetzner — лучший пинг до Еревана среди дешёвых провайдеров, огромный включённый трафик (важно: медиа + WebSocket), и **прод повторяет локалку один-в-один** (тот же `docker compose`).

### Итоговая смета (старт)

| Статья | €/мес |
|---|---|
| Hetzner CX32 (4 vCPU / 8 GB / 80 GB) — всё на одной машине | 6.80 |
| Снапшот-бэкапы Hetzner (+20% от цены сервера) | 1.36 |
| Hetzner Object Storage (бэкапы БД + медиа-архив, 1 TB) | 4.99 |
| Домен (~$12/год) | ~1.00 |
| **Итого** | **~€14/мес (~$15–16)** |

Хорошо внутри бюджета $20–50. Рост: рескейл в пару кликов до CX42 (€16) → CCX-линейка (dedicated vCPU) → вторая машина под Postgres. До ~5–10k активных в неделю одной CX32 хватит с запасом.

> Запасной вариант, если захочется «нулевого админства»: Railway (всё в одном UI, ~$25–40/мес), но дороже и egress за медиа кусается. Fly.io не рекомендую: суммарно дороже и больше движущихся частей.

## 2. Архитектура прода (одна VPS)

```
                    Интернет (только 80/443, ну и SSH 22)
                          │
                 ┌────────▼────────┐
                 │  Caddy (TLS)     │  ← авто-Let's Encrypt
                 └──┬──────┬────┬──┘
     app.anoon.xx ───┘      │    └─── admin.anoon.xx (админка, + basic-auth/IP-allowlist)
     (frontend,          │
      Next.js node)   ┌────┴─────────────────┐
                      │                      │
              ws.anoon.xx              api.anoon.xx
                      │                      │
              ┌───────▼──────┐      ┌───────▼────────┐
              │ Tinode        │◄gRPC─┤ Companion (Go)  │   ← :16060 ТОЛЬКО внутри
              │ :6060 внутри  │:16060│ :8080 внутри    │      docker-сети, наружу НЕ
              └───────┬──────┘      └───────┬────────┘      публикуется
                      │                      │
              ┌───────▼──────────────────────▼───┐
              │ postgres:16 (:5432 только внутри) │
              │ БД tinode + БД anoon               │
              └───────────────────────────────────┘
   volumes: anoon_pgdata, anoon_uploads, anoon_logs, caddy_data
```

**Модель экспозиции портов (главное правило):**
- **Наружу:** только Caddy 80/443 (+ SSH 22 по ключам). UFW: `allow 22,80,443; deny all`.
- **Внутри docker-сети:** Tinode :6060 (HTTP/WS), gRPC **:16060 — только companion↔Tinode, публично НЕ выставляется**, Postgres :5432, companion :8080.
- В прод-компоузе у сервисов **убираем `ports:`** совсем (локальные 6061/16061 — это дев-мэппинг); Caddy ходит по имени сервиса в общей сети.

**Домены** (пример, финальное имя — вопрос ❓):
- `app.anoon.xx` — frontend (PWA).
- `ws.anoon.xx` — Tinode HTTP API + WebSocket + отдача медиа (`/v0/file/s/...`).
- `api.anoon.xx` — companion REST + WS (события рулетки/друзей).
- `admin.anoon.xx` — админка, закрыта basic-auth Caddy + позже своим логином.

## 3. TLS / домен / реверс-прокси — **Caddy**

Caddy, а не nginx/Traefik: авто-HTTPS (Let's Encrypt) без сертификатных скриптов, WebSocket проксирует из коробки, конфиг — 15 строк. TLS-режим самого Tinode (`TLS_ENABLED`) оставляем **выключенным** — терминируем на Caddy.

`Caddyfile` (набросок):

```caddyfile
app.anoon.xx {
    reverse_proxy frontend:3000        # frontend, next start (standalone)
}

ws.anoon.xx {
    reverse_proxy tinode:6060          # HTTP API + WebSocket + /v0/file
}

api.anoon.xx {
    reverse_proxy companion:8080       # REST + companion-WS
}

admin.anoon.xx {
    basic_auth { admin <bcrypt-hash> } # второй замок поверх логина админки
    reverse_proxy admin:3000
}
```

**CORS / куки между фронтом и бэками:**
- Tinode: `FS_CORS_ORIGINS='["https://app.anoon.xx"]'` (сейчас `*` — в проде сузить).
- Companion: `Access-Control-Allow-Origin: https://app.anoon.xx` (+ `admin.anoon.xx` для админки).
- Auth-токены (Tinode token + companion JWT) держим в JS-хранилище приложения, не в куках → CORS-префлайты тривиальны. Если companion всё же ставит сессионную куку: `Domain=.anoon.xx; Secure; SameSite=Lax` — все сервисы под одним родительским доменом, работает.
- `SMTP_HOST_URL` в компоузе сменить на `https://ws.anoon.xx` (ссылки в письмах верификации).

## 4. Медиа-хранилище

Tinode из коробки умеет два хендлера (наш образ уже прокидывает env): `fs` (локальная папка) и `s3` (любой S3-совместимый endpoint через `AWS_S3_ENDPOINT`).

**Рекомендация: старт на `fs` + volume `anoon_uploads`, миграция на S3 по росту.**
- На старте объёмы малы, `fs` проще (нет пресайн-ссылок, CORS-бакетов).
- 80 GB NVMe диска хватит надолго; медиа попадает в ночной бэкап (см. §5).
- Триггер миграции на S3 (Hetzner Object Storage, уже в смете): диск занят >50% ИЛИ захотим CDN. Переключение: `MEDIA_HANDLER=s3`, `AWS_S3_ENDPOINT=https://fsn1.your-objectstorage.com`, ключи из панели Hetzner; старые файлы перелить `rclone`-ом.

## 5. Postgres и бэкапы

**В контейнере на той же VPS (как сейчас), НЕ managed.** Managed PG на Fly — $38/мес, на DO — $15/мес: на старте не оправдано. Нагрузка маленькая, а восстановление отрабатываем бэкапами.

**Схема бэкапов (3 уровня):**
1. **Ночной `pg_dump`** обеих БД (`tinode`, `anoon`) кроном на хосте → сжатый дамп → **загрузка в Hetzner Object Storage** (`rclone`/`restic`, хранить 14 дневных + 8 недельных). Это главный бэкап — офф-машинный.
2. **Hetzner Snapshots/Backups** (+20% к серверу) — снимок всей VPS ежедневно, 7 штук. Быстрое «откатить всё».
3. **`anoon_uploads`** (медиа) — в тот же ночной restic-джоб.

**Restore-тест — часть чек-листа запуска:** поднять пустой compose на локалке, залить последний дамп, убедиться что логинится. Бэкап без теста восстановления — не бэкап.

## 6. Секреты

**Правила:**
- `.env` живёт **только на сервере**: `/opt/anoon/.env`, `chmod 600`, владелец deploy-юзер. В репо — только `.env.example` без значений (сейчас уже так, `.gitignore` есть).
- **Прод-значения ≠ дев-значения.** Все ключи генерим заново для прода.
- Резервная копия прод-`.env` — в парольный менеджер (Bitwarden/1Password), НЕ в git. (Опция для параноиков: `sops`+`age`-шифрованная копия в приватном репо.)

**Ротация ключей — что можно и когда:**

| Ключ | Ротация |
|---|---|
| `API_KEY_SALT` + api-key клиента | **Сделать ДО запуска.** Сейчас соль = апстримный дефолт (известна всем). Собрать `keygen` из исходника (`go build ./keygen`), сгенерить новую соль + новый api-key, зашить api-key в frontend (`NEXT_PUBLIC_TINODE_API_KEY`) и в companion. |
| `AUTH_TOKEN_KEY` | Новый для прода. Позже ротация = разлогин всех (переживаемо), можно менять при инциденте. |
| `UID_ENCRYPTION_KEY` | Новый для прода и **зафиксировать навсегда**: смена после появления юзеров ломает все UID. |
| `POSTGRES_PASSWORD` | Новый длинный; менять можно в любой момент (обновить DSN). |
| Companion (JWT-секрет, OAuth client secret, ключи платёжек) | Там же в `.env`; Google OAuth — отдельный прод-клиент с прод-redirect-URI. |

Секрет-менеджер (Vault и т.п.) на одну VPS — оверкилл; `.env` + права файлов достаточно. Пересмотрим при переходе на 2+ машины.

## 7. Ops: образы, обновления, логи, мониторинг

**Сборка и публикация анон-патченного Tinode:**
- Образ `anoon-tinode` собирается из `server-stack/Dockerfile` (контекст `../server` с нашим патчем анонимности).
- Публикуем в **GHCR приватно**: `ghcr.io/<owner>/anoon-tinode:0.25.2-anon.1` (тег = версия апстрима + номер патча). Аналогично `ghcr.io/<owner>/anoon-companion`, `.../anoon-frontend`, `.../anoon-admin`.
- Сборку можно гнать локально (`docker build && docker push`) или GitHub Actions по тегу — второй вариант, когда код переедет в git-remote.

**Деплой/обновление (простой и почти без даунтайма):**
```bash
ssh anoon-prod
cd /opt/anoon && docker compose pull && docker compose up -d   # пересоздаются только изменённые
```
- Tinode перезапускается за секунды; клиенты (tinode-sdk и companion-WS) обязаны уметь **авто-reconnect** — это и так нужно для мобильных сетей. Настоящий zero-downtime (blue-green) на старте не нужен.
- Порядок при миграциях БД: сначала бэкап (§5), потом `UPGRADE_DB=true docker compose up -d`.
- Откат: `docker compose up -d` с предыдущим тегом образа (теги не перезаписываем).

**Healthchecks / рестарты / логи:**
- Все сервисы: `restart: unless-stopped` + `healthcheck` (у Tinode уже есть `nc -z :6060`; companion — `GET /health`; postgres — `pg_isready`; caddy — сам).
- Логи: docker `json-file` с ротацией — в компоузе глобально:
  `logging: { driver: json-file, options: { max-size: "20m", max-file: "5" } }`.
- Внешний аптайм-пинг: бесплатный UptimeRobot/BetterStack на `https://ws.anoon.xx/v0/...` и `https://api.anoon.xx/health` — узнаём о падении раньше пользователей.
- Хост: `unattended-upgrades` (security-патчи ОС), `fail2ban`, SSH только по ключам, root-логин off.

## 8. Фронтенды

**frontend (PWA юзера) — на той же VPS**, контейнером (`next build` в standalone-режиме → node-образ ~150 MB), за Caddy на `app.anoon.xx`.
- Почему не Vercel: Hobby-план запрещён для коммерции, Pro = $20/мес — дороже всего остального прода вместе взятого. Аудитория — Армения, CDN-география Vercel преимущества почти не даёт (наш сервер и так в 57 мс).
- Что теряем: превью-деплои. Ок для запуска; вернуться к Vercel Pro можно в любой момент — приложение от этого не меняется.

**Админка — там же**, отдельный контейнер на `admin.anoon.xx`, двойная защита: basic-auth на Caddy + собственный логин.

**Env фронта (build-time):**
```
NEXT_PUBLIC_TINODE_HOST=ws.anoon.xx      # tinode-sdk, secure=true
NEXT_PUBLIC_TINODE_API_KEY=<новый после ротации соли>
NEXT_PUBLIC_COMPANION_URL=https://api.anoon.xx
```

## 9. Чек-лист выхода в прод (по фазам)

**Фаза 0 — подготовка (можно уже сейчас):**
- [ ] ❓ Купить домен; DNS на Hetzner DNS или Cloudflare (только DNS, без проксирования WS на старте).
- [ ] Завести Hetzner-аккаунт, создать CX32 (Nuremberg или Falkenstein), Ubuntu 24.04 LTS.
- [ ] Хост: deploy-юзер, SSH-ключи, UFW (22/80/443), fail2ban, unattended-upgrades, docker + compose.
- [ ] Приватный GHCR (или залить код в приватный GitHub — заодно офф-машинная копия репо).

**Фаза 1 — стек на сервере (ещё без пользователей):**
- [ ] Прод-`docker-compose.yml`: + caddy, + frontend, + admin, + companion; **убрать все `ports:` кроме caddy**; логи-ротация.
- [ ] Ротация секретов (§6): новый `API_KEY_SALT` + api-key, новые `AUTH_TOKEN_KEY`/`UID_ENCRYPTION_KEY`/`POSTGRES_PASSWORD`; прод-`.env` на сервер; `SAMPLE_DATA=` (пусто — без демо-юзеров!), `FS_CORS_ORIGINS` сузить.
- [ ] `docker compose up -d` → все healthy; Caddy выдал сертификаты; снаружи открыты ТОЛЬКО 80/443 (проверить `nmap`).
- [ ] Прод-Google-OAuth-клиент с redirect на `api.anoon.xx`.

**Фаза 2 — данные и страховка:**
- [ ] Ночной крон: `pg_dump` + uploads → restic → Object Storage; Hetzner Backups включить.
- [ ] **Тест восстановления** дампа на чистом стенде.

**Фаза 3 — смоук и запуск:**
- [ ] E2E со смартфона из армянской сети (моб. интернет!): регистрация → #ID → рулетка → анон-чат (личность скрыта) → раскрытие → друзья → медиа → PWA-установка.
- [ ] Прогон обновления: `docker compose pull && up -d` без потери данных; прогон отката на прошлый тег.
- [ ] Пуши (E1, VAPID) — прод-ключи.
- [ ] Платёжки (Idram/Telcell/ArCa) — прод-креды, callback-URL на `api.anoon.xx` (по готовности D2).
- [ ] Погасить старый демо-контейнер на локалке, обновить PROJECT-STATUS.md.
