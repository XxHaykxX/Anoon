## 4. Починенные баги

### Настоящие дефекты продукта

| Баг | Причина |
|---|---|
| **Свои сообщения не видны после перезагрузки** | `slices.ts` отбрасывал каждое сообщение с `from == myUid`. Замер: сервер прислал 24 сообщения, 15 своих — отрисовано 0. Пользователь никогда не видел свою половину переписки после перезагрузки. |
| **Каждая отправка уничтожала чужое сообщение** | В кэше SDK у своего сообщения нет `seq`; компаратор даёт `NaN`, двоичный поиск рапортует «нашёл» в середине буфера, оттуда удаляется живое сообщение. Доказано предсказанием: «пропадёт seq 141» — пропал ровно 141. |
| **«Удалить у всех» не доходило до собеседника** | companion искал получателя только в таблице совпадений рулетки; личные переписки туда не пишутся, событие умирало на сервере. Плюс имена личных топиков **разные у каждой стороны** — нужна перезапись под получателя. |
| **Индикатор «отправляет медиа»** | Тот же дефект, тот же фикс. |
| **Фото не грузилось у получателя** | Пузырь — единственный сжимаемый элемент ленты (`overflow:hidden` обнуляет минимальную высоту), при переполнении схлопывался в 0. Фикс: `shrink-0`. |
| **Лента не докручивалась на 400–500 px** | Прокрутка вниз срабатывала до догрузки фото; те занимали высоту позже. Фикс: слежение через ResizeObserver/MutationObserver. |
| **Рулетка: второй участник висел в поиске** | Событие о совпадении слалось «отправил и забыл». Добавлен `GET /roulette/status` + опрос раз в 2 с; оба пути сведены в один обработчик. |
| **Звонки: экран схлопывался молча** | При отказе в доступе к микрофону не было объяснения. Теперь показывается причина. |
| **Поиск друга: `##00012`** | Сервер отдаёт `#ID` уже с решёткой, экран добавлял свою. |
| **Поиск друга: «Добавить» тому, кто уже в друзьях** | Сервер не возвращал `relation`/`avatarTone`, хотя контракт объявлял их обязательными. Починено на сервере + страховка на клиенте. |
| **Рамка телефона обрезалась на 360 px** | Жёсткие 390×844. На iPhone SE и большинстве Android вылезала за оба края (37 px прокрутки вбок); на 1024×768 кнопка «Далее» уходила под сгиб. Фикс: масштабирование по обеим осям. |
| **`/badu` отдавал 404** | Старые закладки и ярлыки PWA вели в пустоту. Добавлено перенаправление 308. |

### 6.2. Безопасность — НАЙДЕНО, НЕ ПОЧИНЕНО

Полный отчёт получен в конце сессии. **Две находки высокого уровня:**

- [ ] **H1. `POST /auth/rest` вообще без авторизации и доступен из интернета.**
      Ветка `del` принимает `uid` как есть и удаляет привязку Google —
      пользователь **навсегда теряет вход**. Восстановиться не может: строка в
      `users` остаётся, а `tinode_uid` уникален. Хуже всего то, что uid не
      секрет: имя личного топика **и есть** uid собеседника, то есть нужное
      значение знает каждый, с кем жертва переписывалась.
      *Фикс:* общий секрет в заголовке + не пускать `/auth/rest` наружу через
      Caddy (Tinode ходит по внутренней сети docker).
- [ ] **H2. Анонимная фаза рулетки выдаёт настоящий постоянный `#ID`.**
      `matched` и `/roulette/status` шлют реальный `#ID` **до раскрытия**. Любая
      сторона может прочитать его с экрана и сразу добавить/заблокировать/найти
      человека без согласия. Это обесценивает и взаимное раскрытие, и серверную
      заплатку анонимности.
      *Фикс:* псевдоним на матч (случайный или `HMAC(match_id, hash_id)`),
      настоящий `#ID` — только в `revealed`. Нужна и правка фронтенда.

Среднего уровня:
- [ ] **M1.** Ограничение частоты запросов **выключено в проде** (не задано
      `RATE_LIMIT_RPS`), а когда включено — обходится: берётся первый элемент
      `X-Forwarded-For`, который подделывает клиент. Брать последний.
- [ ] **M2.** `/auth/rest` без ограничений дёргает проверку Google — усиление.
- [ ] **M3.** Роль админа и `X-Admin-Id` — обычные заголовки. Разделение прав
      декоративное, журнал модерации подделывается.
- [ ] **M4.** WebSocket принимает любой источник (`CheckOrigin` всегда true).

Низкого уровня: L1 жалоба помечает чужие медиа как «эскалированные» (обходит
удаление исчезающих), L2 `/media` принимает любой топик и URL, L3 отписка от
пушей не привязана к вызывающему, L4 в dev-режиме разрешён любой
`*.trycloudflare.com`.

Информационно: `ENV` по умолчанию `dev` — стоит перевернуть, чтобы ошибка
конфигурации давала «слишком строго», а не «нараспашку».

**Проверено и признано здоровым:** SQL-инъекций нет нигде (всё через
параметры), секрет админки сравнивается за постоянное время, авторизация
рулетки корректна, блокировки/жалобы/заявки действуют строго от вызывающего,
сброс пароля на криптостойких одноразовых токенах, `real_gender` только для
админов. **`COMPANION_DEV_AUTH` в порядке**: выключен по умолчанию, прод не
стартует с ним, в проде задан литералом, пишет о себе в лог.

### 6.3. Известные ограничения (решение принято, не баг)

- Восстановленные свои сообщения показывают одну галочку до следующего события
  от собеседника. Лечится `withSub()` в запросе метаданных + доступ к `_users`.
- Загрузчик не пишет размеры картинки, поэтому скелет использует 4:3 и пузырь
  чуть меняет размер при загрузке. Нужна правка пути загрузки и формата.
- Экран `Desktop` в витрине — мокап **другого продукта** (английский интерфейс,
  старый клон Tinode). Не переиспользуется, решить: удалить или переписать.

### 6.4. Десктоп — не начат

Вся «десктопная версия» — одна строка CSS, центрирующая рамку телефона.
В 38 экранах приложения **ноль** адаптивных правил. Полноценный десктоп — это
не проход по брейкпоинтам: телефонная навигация показывает один экран за раз,
десктопному мессенджеру нужен список слева и переписка справа. Оценка: 15–20
файлов плюс переделка маршрутизации.
