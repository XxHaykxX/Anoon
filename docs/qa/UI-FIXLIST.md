## Решения, которые я принял (пункты, вынесенные team-lead на моё усмотрение)

### Р1. Что должен показывать экран входящего звонка

**Решение: `peerName` = «Собеседник», `peerId` = алиас. То есть ровно как в шапке анон-чата.**

Шапка анон-чата (`AnoonAnonChat.tsx:428` + `:882`) уже устроена так: жирная строка —
всегда «Собеседник» (имя появляется только после раскрытия), под ней приглушённая —
handle. Экран звонка сейчас склеивает и то и другое в имя и **повторяет handle
дважды**. Приведение к схеме чата убирает дублирование и даёт двум экранам один
способ описывать одного незнакомца — иначе это самостоятельный дефект.

Отвергнутая альтернатива — убрать handle со звонка совсем. Тогда анонимный звонок
никак не связать с чатом, из которого он идёт: у пользователя может быть открыт чат
с `~K7X2QM`, а звонит «Собеседник» без опознавательных знаков.

### Р2. `tabular-nums` — что убрать, что оставить

Отревизованы **все шесть** мест в `frontend/src`:

| Файл:строка | Что рендерит | Решение |
|---|---|---|
| `components/VoiceMessage.tsx:200` | длительность голосового | **оставить** — цифры, меняются на месте |
| `components/PollMessage.tsx:127` | процент в опросе | **оставить** — цифры, выровнены в столбец |
| `components/RecordingBar.tsx:122` | таймер записи | **оставить** — цифры, тикают на месте |
| `components/anoon/VoiceRecorder.tsx:197` | таймер записи | **оставить** — то же |
| `components/anoon/AnoonAnonChat.tsx:882` | handle собеседника | **убрать** |
| `components/anoon/IncomingCall.tsx:63` | handle собеседника | **убрать** |

Обоснование убрать, а не применять условно (алиас/`#ID`): `tabular-nums` нужен там, где
цифры **выровнены в столбец** или **меняются на месте** — четыре «оставить» ровно такие.
Handle в шапке чата и на экране звонка не делает ни того, ни другого: это единичное
неизменяемое значение. И решающий довод — **ни одно другое место, где показывается
настоящий `#ID`** (строки друзей, результаты поиска, заявки), `tabular-nums` не
использует. Так что снятие класса делает эти два места **согласованными с остальным
аппом**, а не лишает их чего-то. Условное применение — больше кода ради нуля видимой
разницы в `#ID`-случае.

### Р3. Значения фикстур для витрины

**Решение: везде `~SAMPLE`.**

Проверено против `store.aliasAlphabet` (`server-stack/companion/internal/store/roulette.go:22`,
`"ABCDEFGHJKLMNPQRSTUVWXYZ23456789"` — без `I`, `O`, `0`, `1`): `S`,`A`,`M`,`P`,`L`,`E`
все допустимы, длина ровно 6, сигил `~` на месте → строка проходит `store.NormalizeAlias`,
то есть имеет форму настоящего алиаса. При этом «SAMPLE» читается как фикстура и никогда
не будет принято за живой идентификатор.

⚠️ Ловушка при выборе своего значения: очевидные кандидаты **`~DEMO24` и всё с `O`/`I`
недопустимы** — этих букв в алфавите нет. Если менять — сверяться с алфавитом.

Одно значение на все места намеренно: витрина показывает одного вымышленного собеседника,
а не трёх разных.

## Правка 1 — дублированный алиас на экране входящего звонка (пункт 1)

**Файл:** `frontend/src/components/anoon/AnoonApp.tsx` (~349-354, внутри `onCall`)

Сейчас:

```js
        // `from` is server-stamped: a real #ID from a friend, or a per-match
        // anon alias from a roulette peer. The friends lookup simply misses on
        // an alias, which is the intended outcome — an anonymous caller is
        // announced as «Собеседник ~K7X2QM», not by name.
        const from = frame.from ?? "";
        const peerName = friends.find((f) => f.hashId === from)?.displayName ?? `Собеседник ${from}`;
```

Заменить на:

```js
        // `from` is server-stamped: a real #ID from a friend, or a per-match
        // anon alias from a roulette peer. The friends lookup simply misses on
        // an alias, which is the intended outcome — an anonymous caller has no
        // name to show.
        //
        // The handle rides in `peerId` alone. Interpolating it into the name too
        // printed it twice, stacked, on the ringing screen. The anon chat header
        // already splits these — a generic «Собеседник» over the muted handle
        // (AnoonAnonChat: headerName + partnerId) — so both screens now describe
        // the same stranger the same way.
        const from = frame.from ?? "";
        const peerName = friends.find((f) => f.hashId === from)?.displayName ?? "Собеседник";
```

**Почему:** экран звонка показывал `Собеседник ~K7X2QM` и под ним `~K7X2QM` — один и тот
же алиас дважды; до этой волны путь не существовал, потому что звонки шли только между
друзьями с настоящим именем.

### Правка 1b — не рисовать пустую строку handle (укрепление, там же)

**Файл:** `frontend/src/components/anoon/IncomingCall.tsx:63`

Сейчас:

```jsx
          <p className="text-sm tabular-nums text-foreground/50">{peerId}</p>
```

Заменить на (совмещено с правкой 2 — класс `tabular-nums` тоже уходит):

```jsx
          {peerId && <p className="text-sm text-foreground/50">{peerId}</p>}
```

**Почему:** `frame.from` может прийти пустым (`from = frame.from ?? ""`), и тогда под
именем рендерился пустой абзац, дающий лишний зазор в `gap-1.5`-колонке.

> Побочный эффект правки 1, который надо принять сознательно: `toneFor(peerId)`
> (`IncomingCall.tsx:38`) считает тон аватара из handle. Он не менялся, но теперь для
> анонимного звонящего тон берётся из алиаса, а алиас у одного и того же человека в
> каждом матче новый — цвет аватара будет разным от матча к матчу. Это **правильно**:
> узнаваемость возвращающегося собеседника — ровно то, что H2 убирает.

## Правка 3 — лист жалобы (пункт 3)

**Честная переоценка: то, чего я опасался в `SCREEN-MAP.md` §6.3, дефектом не является.**
Я предполагал, что новый блок ошибки может вытолкнуть кнопку «Отправить» за нижний край.
Перечитал разметку: контейнер листа — `max-h-[92%] overflow-y-auto`
(`AnoonReport.tsx:122`), то есть он **скроллится**, а блок ошибки стоит непосредственно
над кнопкой, у которой в этом же состоянии меняется подпись на «Отправить ещё раз».
Видна кнопка — виден и блок. **Патч не нужен**, состояние остаётся в чек-листе
(`QA-SECURITY-WAVE.md` §3.2) как «посмотреть глазами», не более.

Патчить здесь имеет смысл только одно — фолбэк-подпись, и она же пункт 8:

**Файл:** `frontend/src/components/anoon/AnoonReport.tsx:48`

Сейчас:

```js
  const peerLabel = target.name ?? (peerHashId ? `Собеседник #${peerHashId}` : "Собеседник #04821");
```

Заменить на:

```js
  const peerLabel = target.name ?? (peerHashId ? `Собеседник #${peerHashId}` : "Собеседник ~SAMPLE");
```

**Почему:** «#04821» — правдоподобный несуществующий `#ID` в качестве заглушки; на
витрине лист жалобы рендерится без стора и показывает именно его, обучая ровно тому,
что H2 запретил.

> Длинная подпись (`Собеседник ~K7X2QM` вместо `Собеседник #00012`) выводится в
> `AnoonReport.tsx:100` внутри декоративной подложки (`pointer-events-none opacity-40`),
> блок полноширинный и без `truncate` — переносится, не обрезается. Правка не требуется.

## Что я хочу отдать вам, а не решать сам

### Д1. Нужен ли handle на экране входящего звонка вообще (низкие ставки)

Я оставил его (Р1) ради связи со «своим» чатом. Контрдовод: для анонимного звонящего
это строка, с которой пользователь **ничего не может сделать** — не найти, не добавить,
не пожаловаться по ней. Если продуктово решено, что незнакомец на экране звонка не
должен иметь видимого идентификатора вовсе, правка сводится к удалению строки
`{peerId && …}` из `IncomingCall.tsx`. Обратимо в одну строку, поэтому я не блокировался.

### Д2. Лист жалобы вообще без цели — продуктовый вопрос

`AnoonReport.tsx:48` подставляет вымышленного собеседника, когда нет ни активного матча,
ни открытого чата. Я меняю только вид заглушки (`#04821` → `~SAMPLE`), но настоящий
вопрос — **должен ли экран жалобы открываться, когда жаловаться не на кого**. Сейчас он
откроется, соберёт причину и комментарий и отправит запрос без `reportedHashId` и без
`topic`, который companion отклонит как `missing_target` (`reports.go`, ветка `default`)
— и пользователь увидит новый блок «Не удалось отправить жалобу», хотя дело не в
соединении. Варианты: не давать открыть, показать явное «не выбран собеседник», или
оставить как есть. Это решение уровня продукта, не патч.

### Д3. Пустой фолбэк handle в анон-чате

`AnoonAnonChat.tsx:426` — `activeMatch?.peerAlias ?? "—"`. Голое тире рядом со
статус-точкой в момент, когда алиас ещё не приехал (перезагрузка страницы в анон-чате,
путь восстановления через `/roulette/status`). Раньше было `"#—"`. Оба варианта
одинаково невнятны; осмысленный вариант — не рисовать строку вовсе, пока handle
неизвестен, как в правке 1b. Держу как предложение, не как правку: это заметно только
в узком окне и лучше сначала посмотреть глазами.
