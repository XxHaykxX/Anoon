# anoon — Полный аудит и рекомендации (2026-07-04)

Глубокий аудит фронта (`frontend`), бэкенда (`companion`, Go) и админки (`admin`):
что не подключено, что было на моках, что мёртвое. Ниже — что уже исправлено агентами в этой
сессии, что осталось на тебя, и рекомендации в порядке приоритета.

Обе сборки после всех правок зелёные: `frontend` `tsc --noEmit` = 0 ошибок;
`companion` `go build/vet/test` = OK.

## 1. Что БЫЛО не так (найдено аудитом)

### Фронтенд (frontend)
- **Половина экранов на хардкоде.** Notifications, Settings, Report, Invite, часть Home —
  фейковые массивы вместо store/companion. Даже в реальном режиме (`USE_TINODE=1`) не читали бэкенд.
- **Мёртвые кнопки:** «Выйти»/«Выход» (нет logout), «Сменить фото», «Сохранить», «Скопировать ссылку»
  (не писала в буфер), колокол на Home, ряды в Settings, кнопки звонка, микрофон, вложения.
- **Фейковый вход:** OAuth-кнопки (Google/FB/Apple) кидали в `home` БЕЗ авторизации.
- **Нет входа для существующих аккаунтов** — только регистрация создавала юзера.
- **Регистрация теряла пол/возраст/имя** в реальном режиме (пропускала экраны сбора). Пол критичен для матчинга.
- **Блокировка собеседника** только мигала баннером.
- **3 недостижимых роута** (conversation-ended/reveal-prompt/offline — inline/overlay-триггеры).

### Бэкенд (companion, Go)
- **Модерация ~0%:** `POST /reports` = заглушка 501; `Ban`/`Mute` = «not implemented» ошибки.
- **Админ-API не существовал** — ни одного `/admin/*`, ни shared-secret, ни presence-трекера.
- **Нет таблиц** bans / moderator_actions / media_assets; `reports` была, но без кода.
- **Orphan-аккаунт**: при сбое аллокации #ID Tinode-аккаунт утекал (не чистился).
- Приоритет очереди по тарифу захардкожен в 0 (ждёт монетизацию).

### Админка (admin)
- **Целиком на фикстурах.** «api-режим» смотрел в Supabase, НЕ в companion. Свап на companion — 0%.
- **Мёртвый глобальный поиск** в шапке (без state/onChange).
- **СЕКРЕТЫ В ДЕРЕВЕ:** `.env` с реальным `SUPABASE_SECRET_KEY`, `ADMIN_SESSION_SECRET`,
  плейнтекст `ADMIN_PASSWORD`; `.env.local` с живым Vercel OIDC токеном.

## 2. Что УЖЕ исправлено в этой сессии (агентами)

**Фронт (frontend) — всё с `tsc` = 0:**
- Logout в Профиле и Настройках → `signOut()` → onboarding.
- Профиль: копирование ссылки в буфер, выбор фото (превью), Save persist в store.
- Home: колокол → notifications, реальный бейдж-счётчик, реальное имя/инициалы.
- Invite: реальный `#ID` и ссылка из store.
- **Вход по email/паролю** для существующих аккаунтов (реиспользован `signInWithBasic` login-ветка + подтягивание профиля через `companion.me()`).
- OAuth: убран фейковый вход; Google = «Скоро» (ждёт креды), FB/Apple скрыты.
- Регистрация тянет пол+возраст+имя в `companion.register`.
- Notifications подключены к store + companion (accept/decline → `friendRespond`).
- Settings: ник persist, ряды навигируют, push → `Notification.requestPermission()`.
- Report → `companion.report()` → `POST /reports` с реальным peer #ID.
- Searching показывает реальные выбранные фильтры.
- Чат: звонки скрыты (Phase F), вложения шлют placeholder-бабл, микрофон с аффордансом «скоро».
- Блокировка собеседника → `companion.block()` → завершает матч.
- Explicit onClick на back в анон-чате; недостижимые роуты задокументированы как QA-only.

**Бэкенд (companion) — `go build/vet/test` = OK:**
- Миграция `0004_moderation.sql`: bans, moderator_actions, media_assets, `users.real_gender`, `users.last_seen`.
- `POST /reports` реализован (запись в reports).
- Ban/Unban через ROOT `{acc state:susp/ok}`; Mute/Unmute (mute_until + drop W); enqueue отклоняет забаненных/мутнутых.
- **Полный админ-API** `/admin/*` с `X-Companion-Admin-Secret` + `X-Admin-Id/Role`, конверт `{data,total}`, пагинация/фильтры (Refine-совместимо): reports, users (ban/mute), bans, overview, online.
- Presence-трекер: `last_seen` обновляется на WS-connect/pong и на authed REST.
- Orphan-очистка Tinode-аккаунта при сбое #ID.
- `POST /roulette/block`: friendships='blocked' + симметричное исключение в матчинге (anti-abuse).

**Админка (admin) — `tsc` = 0:**
- Живой глобальный поиск в шапке (по нику/#ID, фильтрует Users в обоих режимах).
- **companion-client** + переключатель `ADMIN_BACKEND=companion|supabase`: reports/users/bans/overview/online теперь могут ходить в реальный companion (Supabase сохранён как fallback).
- Секреты: `.gitignore` правит, `.env.example` с плейсхолдерами, `SECURITY.md` с планом ротации.

## 3. Что ОСТАЛОСЬ — нужно ТВОЁ вмешательство (примени это)

1. **Ротация секретов (СРОЧНО, безопасность).** Секреты были в дереве. Нужно:
   - Ротировать `SUPABASE_SECRET_KEY`, `ADMIN_SESSION_SECRET`, Vercel OIDC токен.
   - `ADMIN_PASSWORD` не хранить плейнтекстом — только argon2-хэш в таблице `AdminUser`.
   - Если репо когда-либо был в git с этими значениями — почистить историю (`git filter-repo`) или считать их скомпрометированными. Детали в `admin/SECURITY.md`.

2. **Google-вход (было заблокировано на тебе).** Нужен `GOOGLE_CLIENT_ID` из Google Cloud + rest-auth блок в Tinode `.conf` + `COMPANION_GOOGLE_CLIENT_ID`. Код брокера готов.

3. **Юр. вопрос по чатам админки (#67).** `GET /admin/chats` требует решения: модератор видит ВСЕ приватные чаты или только пожалованные? До решения не реализуем (приватность/комплаенс).

4. **Монетизация (#68).** Приоритет очереди по тарифу оживает только с подписками — нужны решения по платежам (Idram/Ameriabank, ИП, `PAYMENTS-PLAN.md`).

5. **Прод-деплой.** Локально всё в Docker. Нужен сервер (Hetzner) + домен + DNS + секреты (`DEPLOY-PLAN.md`).

## 4. Рекомендации по приоритету

- Ротировать секреты (см. выше).
- Прогнать сквозной ручной E2E: регистрация → вход → рулетка (2 окна) → reveal → друг → жалоба → бан из админки (с `ADMIN_BACKEND=companion` + `COMPANION_ADMIN_SECRET`).
- Включить `COMPANION_ADMIN_SECRET` в compose и `ADMIN_BACKEND=companion` в админке — проверить живой поток reports/users/bans.
  ⚠️ **`ADMIN_BACKEND=companion` одного недостаточно**: нужна пара с
  `NEXT_PUBLIC_DATA_MODE=api`, и задать её надо **на этапе сборки** админки —
  `NEXT_PUBLIC_*` подставляется в бандл при `next build`. Собранная в mock-режиме
  админка, запущенная с api-переменными, молча остаётся на `mockDataProvider`:
  разделы выглядят рабочими, показывают фикстуры и не делают к companion ни
  одного запроса. Проверять этот пункт по фикстурам — значит не проверить ничего
