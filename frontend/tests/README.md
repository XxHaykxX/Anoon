# E2E-тесты frontend (Playwright)

Функциональные end-to-end тесты для PWA **anoon** (Next.js), которые прогоняют
приложение целиком в браузере в **mock-режиме** — без бэкенда (companion/Tinode).

## Что нужно перед запуском

`@playwright/test` **ещё не установлен** в проекте (он добавлен только в
`devDependencies` в `package.json`). Перед первым запуском:

```bash
npm install                 # подтянет @playwright/test
npx playwright install      # скачает браузеры (Chromium)
```

## Как запускать

Тесты ходят в уже запущенный dev-сервер — Playwright сам его не поднимает.

1. Запустите приложение в **mock-режиме**. Важно: переменная
   `NEXT_PUBLIC_USE_TINODE` должна быть **не задана** (или не равна `"1"`),
   иначе приложение попытается ходить в реальный бэкенд и тесты не пройдут.

   ```bash
   npm run dev                 # http://localhost:3001
   ```

2. В другом терминале:

   ```bash
   npm run test:e2e            # прогнать всё
   npm run test:e2e:ui         # интерактивный UI-режим Playwright
   npm run test:e2e:report     # открыть HTML-отчёт после прогона
   ```

### Другой адрес приложения

По умолчанию база — `http://localhost:3001`. Переопределяется через `BASE_URL`:

```bash
BASE_URL=http://localhost:3000 npm run test:e2e
```

Все тесты открывают маршрут `/anoon` (приложение стартует на экране онбординга).

## Важное про режимы

- В **mock-режиме** (`!USE_TINODE`) mock-*драйвер* companion
  (`src/lib/companion.ts`, таймеры `matched`/`reveal`) **не используется** —
  `enqueue()` вызывается только при `USE_TINODE`. Экран «Ищем собеседника…»
  сам переходит в чат по внутреннему таймеру ~1.5 c, а карточка раскрытия
  профиля показывается сразу (`showReveal = !USE_TINODE`).
- Селекторы устойчивые: везде, где возможно, используются `getByRole` /
  `getByText` / `getByPlaceholder` с русскими подписями, а не CSS-классы.
- Viewport выставлен в **390×844**, чтобы совпадать с CSS-«рамкой телефона».

## Ручное QA через Playwright MCP

Если гоняете экраны вручную через Playwright MCP (браузер под управлением
агента), работайте **строго по одной вкладке за раз** — параллельные вкладки в
MCP-сессии мешают друг другу и дают ложные падения.

## Селекторы, которые стоит проверить при первом прогоне

Несколько мест, где подпись/структура не проверялись вживую (см. отчёт):

- Онбординг → регистрация делается кликом по точке-индикатору `Слайд 4`, затем
  «Начать». Если у последнего слайда другая логика — используйте 3× «Далее».
- Приглашение друга (`smoke`) кликается по `getByLabel("Пригласить друга")` —
  это `<svg aria-label>`, а не `<button>`.
- Экран «Найти друга» открывается иконкой поиска без `aria-label` — в текущем
  наборе тестов он намеренно не покрыт (нестабильный селектор).
