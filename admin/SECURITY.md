# Security notes — anoon-admin

## Secrets that were committed and MUST be rotated

The following secrets were present in the working tree (`.env`, `.env.local`) and are
considered **compromised** — they must be rotated by a human before/at production launch.
Do not treat any of these current values as safe.

- `SUPABASE_SECRET_KEY` — rotate in Supabase dashboard (Project Settings → API →
  service/secret key). Update `.env` afterwards.
- `ADMIN_SESSION_SECRET` — regenerate a fresh 32+ char random string. Rotating it
  invalidates all existing admin session cookies (everyone re-logs-in — that is fine).
- `ADMIN_PASSWORD` — was stored **in plaintext**. Rotate the admin password and
  re-run the admin bootstrap so only the argon2 hash is persisted (see below).
- `VERCEL_OIDC_TOKEN` (in `.env.local`) — short-lived, regenerated by the Vercel CLI;
  no manual rotation needed, but it must never be committed.

## Rules going forward

- `.env`, `.env.local`, and `.env*.local` are gitignored. Only `.env.example`
  (placeholders, no real values) is committed. See `.gitignore`.
- **Never** store `ADMIN_PASSWORD` in plaintext anywhere persistent. The admin
  credential of record is the **argon2 hash** in the `AdminUser` table
  (the app already depends on `@node-rs/argon2`). `ADMIN_PASSWORD` in `.env` is a
  one-time bootstrap input for `scripts/create-admin.mjs`; clear it after the first
  admin is created.
- Secret keys must never carry a `NEXT_PUBLIC_` prefix — that would bundle them to
  the client. Keep server-only secrets server-only.
